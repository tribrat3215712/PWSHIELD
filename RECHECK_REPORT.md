# Повторная проверка PZShield Core 1.1.1

Дата: 8 октября 2026 года. Целевая версия: Project Zomboid Dedicated Server **42.21.0**, ревизия **4a0e9546ec**, Java 25.

## Что проверялось

Повторно проверены патчи байткода, очереди, освобождение сетевых буферов, конфигурация, метрики, wire-формат физики транспорта и штатные права управления. Три независимых направления аудита дополнены запуском настоящего локального Dedicated Server с установленными игровыми ресурсами и нативными библиотеками.

В присланном `java-4.zip` конфигурация PZShield не соответствовала версии JAR. Классов PZShield и ссылок на его настройки в исходном JAR не было. Существование других модификаций этим не исключается. Для 1.1.1 подготовлен новый конфиг с параметрами реализованного кода.

## Проверка живого сервера

Стенд использует отдельные профили в `audit/live`, отдельные миры без модов, `-nosteam`, `Public=false`, `UPnP=false`, RCON выключен. Порты привязаны к **127.0.0.1**. Установленные Steam JAR и сохранения пользователя не заменялись. Игровые ресурсы скопированы в стенд; нативные библиотеки и Java используются из установленного Dedicated Server.

Исходный JAR: профиль `audit/live/baseline-full`, порт 17261, PID 8812. Сервер загрузил мир и дошёл до `*** SERVER STARTED ****`; команды `players` и `quit` отработали, мир сохранился, процесс завершился с кодом **0**. Лог: `audit/live/baseline-full/launcher.log`.

Исправленный JAR: профиль `audit/live/patched-full-verified`, порт 17271, PID 3624, отдельная неизменяемая копия JAR. Сервер загрузил мир, вывел `*** SERVER STARTED ****` и `[PZShield 1.1.1] compiled hooks loaded; enabled=true`. Проверка системных UDP endpoints подтвердила адрес **127.0.0.1:17271**.

Настоящий клиент native RakNet подключился с тестовым паролем, получил ID16 и отправил четыре коротких некорректных frame. Получен ID21 отключения; клиент завершил native peer и вышел с кодом **0**. В серверном CSV `invalid_total` вырос до **3**, `backlog_bytes` остался **0**, сервер продолжил тики. Четвёртый frame ID25 нельзя приписать Java guard по этому прогону: он может обрабатываться самим RakNet. Лог клиента: `audit/live/native-probe-verified.log`.

Команды `players` и `save` после этой проверки обработаны: 0 игровых игроков, `Saving finish`, время сохранения около 55 мс. Это функциональная проверка команды; она не является сравнительным тестом производительности.

Второй native-клиент отправил настоящий игровой `Ping` (тип 114, 14 байт) и получил правильный ответ: echo `127.0.0.1`, соединений 1, максимум игроков 4. Затем `PlayerUpdateReliable` (тип 13) до Login был отклонён штатной pre-auth проверкой до разбора игрового тела. Клиент получил ID21 и завершился с кодом **0**. Серверные метрики: `accepted_total=2`, `payload_bytes_total=11`, `invalid_total=3`, `preauth_total=1`, `peak_backlog_bytes=2176`, **`backlog_bytes=0`**. Это проверяет реальную очередь и освобождение буфера в нормальном и отвергнутом проходах. Лог: `audit/live/native-queued-probe-verified.log`.

После всех проверок команды `players` и `quit` отработали, мир сохранился, появилась строка `Shutdown handling finished`. Сервер завершился **с кодом 0** в 19:56:13 UTC. Продолжительность запуска около 7 минут; после старта обработано 3759 тиков. Работающий тестовый процесс не оставлен.

Предупреждения об игровых ресурсах, свойствах worldgen, зонах карты и повторяющемся RoomDef встречались и на исходном сервере. После нормализации номера кадра и времени оба лога содержат один и тот же набор из **48 уникальных строк `ERROR:`**. После `SERVER STARTED` новых строк `ERROR:` или стеков исключений в исправленном сервере не обнаружено. Неудачные подготовительные запуски стенда сохранены отдельно: сначала сканер игры не обходил junction `media`, затем тестовый JAR читался одновременно с пересборкой. Ресурсы скопированы, а итоговый запуск выполнен с отдельной полной копией проверенного JAR.

## Границы результата

Проверены настоящий запуск Dedicated Server, соединение native RakNet, обработка сетевого входа, работа консоли и сохранение отдельного мира. Native RakNet/Bullet загружаются сервером, но отдельная игровая поездка и симуляция машины с настоящим игроком не выполнялись. Полный клиент, успешный игровой Login, несколько игроков, split-screen в живой игре, моды и длительный онлайн под нагрузкой остаются непроверенными. Логические права владельца, смена владельца и split-screen проверены интеграционными тестами игровых объектов.

Из этих результатов нельзя вывести процент роста FPS, полное отсутствие рассинхрона или обнаружение всех читов. Квоты PZShield ограничивают отслеживаемые Java-буферы, а не всю JVM, native-очереди и внешний UDP-трафик. Rate enforcement по умолчанию выключен: пороги следует выбирать по реальному трафику.

Остаточное ограничение внутреннего API: специальные очереди используются штатным кодом через `add/offer/poll`; наследуемые массовые и произвольные мутации `ConcurrentLinkedQueue` не поддерживают их счётчики. Анализ исходного JAR не нашёл таких вызовов к подменённым очередям. Моды, меняющие эти приватные очереди через reflection, требуют отдельной проверки.

Версия **1.1.1 заменяет 1.1.0** для установки. Откат: остановить сервер и вернуть исходный JAR и конфигурацию.
